# Synthetic Patient Data Retrieval

Streamlit app that queries synthetic patient records with a RAG workflow. Data is generated by Synthea, loaded into SQLite (`data/sqlite/patient.db`), and retrieved from `src/`. This is **SQLite**, not MySQL.

## Pipeline

1. Synthea JAR writes FHIR Bundles under `data/generator/output/fhir/`.
2. `PatientDatabaseManager` in `loadGeneratorData.py` parses Patient, Encounter, Condition, Observation, MedicationRequest, and Procedure resources into SQLite.
3. `rag_retrival.py` turns each table row into a LangChain `Document` (sparse `page_content` + metadata IDs). Chroma embedding/retrieval is still the leftover skeleton.
4. `app.py` is the Streamlit query form; it is not wired to retrieval yet.

## Retrieval direction (see README.md)

Do not add a second vector database. Keep vectors and FTS in `patient.db` with **sqlite-vec** (`vec0` KNN) + **FTS5** (BM25), merged with Reciprocal Rank Fusion. Build **encounter-level documents** that denormalize identity + clinical facts; use row-level chunks as pointers and JOIN back to full patient/encounter context. SQL filters (`patient_id`, dates, `resource_type`) run before hybrid search.

`all-MiniLM-L6-v2` is fine to start (384-d). Do not treat Synthea rows like PDF pages with `RecursiveCharacterTextSplitter`.
